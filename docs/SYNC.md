# GitHub 数据同步

适用于 Windows 版 TinyTodo 3.7.0 及以后版本。

在设置中填写 GitHub 私有仓库链接。Token 环境变量名留空时使用本机 Git Credential Manager 的现有登录；填写后仅使用指定变量，不会在授权失败时换用另一账户。界面和任务文件仅保存变量名。

需要 token 时，在 Windows 环境变量设置中保存 token，再填写变量名。Fine-grained token 需选择目标仓库并授予 Contents 读写权限。参考 [GitHub 权限说明](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)。

保存设置后启用自动同步。Push/Pull 按钮也会保存当前仓库与授权设置；其他未保存的设置保持原样。清空仓库链接并保存可停用。

- 启动时 Pull。每次任务数据保存后排队 Push，连续更新合并为一次请求；窗口位置等本机设置不会触发上传。
- 网络操作在后台串行进行。断网或授权失败时，本机任务仍正常保存，状态显示在设置中；可手动重试，下次更新或启动也会重试。
- 使用默认分支中的 `tinytodo-data.json`，包含任务、循环系列与专注记录。不包含本机窗口位置、猫猫黑名单、数据路径、仓库配置或 token。
- 以最近一次同步版本为基准合并。不同任务及不同字段可合并；同一字段修改或删除与修改冲突时暂停自动同步，在设置中选择“采用本机”或“采用云端”，确认后替换。
- Pull 保留原任务文件为 `tasks.json.bak`。Push 使用 GitHub 文件 SHA 防止覆盖传输期间的新修改；云端旧版本仍保留在提交历史中。
- 同步涉及正在编辑或专注的任务时暂缓应用；保存／关闭编辑窗口或结束专注后再同步。
- 同步基准保存在本机数据位置配置目录的 `sync-state.json`。迁移任务目录不改变此基准。卸载勾选清理数据会移除本机同步记录，不删除 GitHub 仓库。
- 正常退出会尝试上传最后修改；上传失败时允许退出，本机数据保留。不要同时用不同任务文件连接同一个仓库，除非确实希望合并它们。

其他系统的应用暂未实现。
